# 输入 — 内化 — 输出：个人知识工作流设计

> 本文回答一个问题：**把「搬运 → 消化 → 讲清楚」这条流水线，变成应用里可以每天走的路径。**
>
> 内化阶段的知识单元设计（Note / Block / Card、`.rnote/` 排期）已经在
> [`rnote-design.md`](rnote-design.md) 里定稿并验证过，本文不重复，只补它没覆盖的两端：
> **输入怎么进来、输出怎么沉淀**，以及把三段串起来的**状态模型与工作台**。

---

## 0. 一页速览

| 阶段 | 你要做的事 | 应用里对应什么 | 关键设计 |
| --- | --- | --- | --- |
| **① 输入** | 录音、教材、课程、灵感，**不做加工**先搬进来 | `00-输入/`（收件箱 + 材料）+ 快速捕获浮层 | 低摩擦：一键捕获、不强制分类、允许乱 |
| **② 内化** | 思考、归纳、抽象、举例、实践；造卡；反复复习 | `10-内化/` 里的 Block / Card + FSRS 复习视图 | 加工有**脚手架**，记忆有**排期**，程度可**量化** |
| **③ 输出** | 用自己的话讲清楚、写清楚，归档进知识库 | `20-输出/` 的成品笔记 + 来源面板 | **来源可追溯**，遗忘能回流重学 |
| — | 贯穿三段 | **工作台**：今日待办 + 三列看板 | 每天打开就知道该干什么 |

一句话：**三个文件夹是"东西在哪"，一个状态字段是"它到哪一步了"，一个工作台是"我今天该干嘛"。**

---

## 1. 三条设计原则

**① 捕获必须无摩擦，加工必须高门槛。**
两端的标准要相反。收集时任何"这个该放哪儿"的犹豫都是摩擦，所以捕获**只需要一个快捷键、一个输入框**，落点是固定的一篇收件箱。反过来，写进 `10-内化/` 的东西必须是你自己的话——所以内化阶段要有脚手架逼你想，而不是让你复制粘贴。

**② 状态写在文件里，进度写在仓库里。**
和 `rnote-design.md` §2.4 同一个道理：**低频写的东西（笔记状态）跟着文件走，高频写的东西（复习进度）跟着仓库走**。状态是 frontmatter，复习进度是 `.rnote/`。

**③ 三层结构永远是"可选"的。**
不写 frontmatter、不写 `?` 卡片，它就是一个普通的 Markdown 仓库。**任何一天你不想玩了，笔记一行都不会丢，用 Obsidian / VS Code 打开一切照旧。** 这条是底线，不因为加了工作流而改变。

## 2. 状态模型：三个阶段怎么落在文件上

### 2.1 物理结构：收集区是一个真实的地方

```
仓库/
  00-输入/                 ← 收集区：原样搬进来，允许乱
    收件箱/
      2026-10-06.md        ← 快速捕获的落点（按天一篇，自动创建）
    材料/
      得到·心理学课 第3讲.md  ← 导入音视频/PDF 时自动生成的"材料卡"
      如何阅读一本书 摘录.md
  10-内化/                 ← 加工区：你的理解在这里成形
    检索练习为什么有效.md
    卡片盒笔记法.md
  20-输出/                 ← 成品区：讲清楚了、能给人看的
    我是怎么用卡片盒记笔记的.md
  90-归档/                 ← 消化完的材料、过时的旧稿
  attachments/             ← 全仓库共用的附件（录音、PDF、截图）
  .rnote/                  ← 复习排期与历史（见 rnote-design §2.4）
```

**为什么收集区必须是真实文件夹**：因为捕获那一瞬间你不能做决定。落点固定、可以乱、可以重复，是这个阶段的全部要求。而 `00-输入/` 天然承担了这个角色，也提供了一个"清空它"的仪式感（见 §3.3）。

### 2.2 状态字段：一个词汇表，四个状态

frontmatter 里只加一个 `status`：

```markdown
---
status: inbox
type: course          # note | course | book | article | clip | idea | output
source: https://...   # 可选：原始出处
captured: 2026-10-06  # 捕获日期，用来算"积压了多久"
---

# 得到·心理学课 第3讲

![[第3讲.m4a]]

## 原文摘录
…

## 我的加工
…
```

| status | 界面上的话 | 含义 |
| --- | --- | --- |
| `inbox` | **待处理** | 还没加工，允许是原始材料 |
| `internalizing` | **内化中** | 已经在写自己的理解 / 已经挂了卡片在复习 |
| `output` | **已输出** | 已经是成品，能给人看 |
| `archived` | **已归档** | 材料消化完了、旧稿过时了；默认不出现在看板 |

中文值也认（`输入 / 内化 / 输出 / 归档`），解析时归一化——手写 frontmatter 时不用查词典。

### 2.3 为什么不全用文件夹，也不全用状态

| 只用文件夹 | 只用状态 | **采用：文件夹给默认值，状态给真相** |
| --- | --- | --- |
| 输出写完要挪文件，挪完 wikilink、反链、"最近打开"全乱；一篇文章产出三篇输出时无处安放 | 文件树变成一坨，找东西全靠看板 | 目录提供**默认归属**（`00-输入/` 里的笔记默认 `inbox`），状态字段允许**就地升级**，两者不一致时以状态为准 |

规则很简单：**新文件按目录推断状态，之后以 frontmatter 为准。** 没有 frontmatter 的老笔记不进看板，安安静静待在文件树里——零打扰。

### 2.4 生命周期与回流

```
   捕获                 开始加工              写成成品            材料消化完
     │                     │                    │                   │
     ▼                     ▼                    ▼                   ▼
  [inbox] ──────────► [internalizing] ─────► [output] ────────► [archived]
     ▲                     │  ▲                 │
     │                     │  │                 │  输出也可以挂卡：
     └─────────────────────┘  └─────────────────┘  忘了 → 复习 → 跳回成品
        材料看不懂，退回重读        输出讲不清，退回重想
```

**回流是这套设计的关键。** 知识工作不是流水线，是会倒回去的：输出的文章被人问住了 → 退回内化补卡片；复习时发现某个 Block 完全想不起来 → 退回材料重读。看板要支持**拖回上一列**，而不是只允许单向前进。

## 3. 阶段一：输入（低摩擦捕获）

### 3.1 快速捕获

**快捷键 `Ctrl` + `Shift` + `I`**，弹出一个小浮层：

```
┌──────────────────────────────────────┐
│ 记一笔…                              │
│ ┌──────────────────────────────────┐ │
│ │ 刚才那个例子很适合解释锚定效应    │ │
│ └──────────────────────────────────┘ │
│ [回车] 存进收件箱   [Ctrl+回车] 存并加工 │
└──────────────────────────────────────┘
```

- 落点固定：`00-输入/收件箱/YYYY-MM-DD.md`，不存在就创建
- 每条追加成一行带时间的 bullet：`- 14:32 刚才那个例子很适合解释锚定效应`
- **粘贴链接自动变 Markdown 链接，粘贴图片自动存进 `attachments/` 并插入 `![[...]]`**
- `Ctrl + 回车` = 存完立刻跳到"加工"（给那种已经想清楚了的灵感）

设计要点：**浮层里没有"选择文件夹"这个控件**。要分类？等清收件箱的时候再说。

### 3.2 材料导入：教材、课程、录音

**`Ctrl` + `Shift` + `M`**，或者把文件直接拖进窗口：

1. 文件（音频/视频/PDF/EPUB/图片）复制进 `attachments/`
2. 在 `00-输入/材料/` 生成一篇**材料卡**：

```markdown
---
status: inbox
type: course
source: 得到 App · 心理学基础 · 第 3 讲
captured: 2026-10-06
---

# 得到·心理学课 第3讲

![[第3讲.m4a]]

> 时长 42 分钟 · 导入于 2026-10-06

## 原文摘录

（听/看的时候往这里丢要点，不求完整）

## 我的加工

（加工从这里开始：用自己的话、举自己的例子）
```

材料卡就是**这个阶段的工作台**：上面是原料，下面是你的加工区，一屏之内完成"对照着写"。

### 3.3 待处理清单与积压老化

`00-输入/` 的东西按 `captured` 排序，显示**积压天数**：

```
待处理 · 7 件
  ▸ 得到·心理学课 第3讲      课程   刚刚
  ▸ 如何阅读一本书 摘录       书     3 天
  ▸ 那条关于间隔重复的推文     剪藏   12 天   ⚠️
```

- 超过 14 天标黄，超过 30 天标红——**不是为了让你内疚，是为了让"该删就删"变得容易**
- 每条有三个动作：**加工**（→ 内化）、**归档**（材料留着，标记已读）、**删掉**（承认这条不会看了）
- 清收件箱的正确标准不是"全部处理完"，而是"每一件都做了决定"

### 3.4 AI 转录（可选，第三阶段再上）

录音最有价值的加工是**转录**，但本地 Whisper 太重、云 API 又涉及隐私。设计成可选项：

- 材料卡上有「转录」按钮，调 OpenAI 兼容的 `audio/transcriptions` 接口
- 转录结果写进材料卡的「原文摘录」区，带时间戳
- **转录只是把声音变成字，仍然是原料**，不越过"不加工"的原则
- 不想用云 API 的话，这条功能整个可以不用，材料卡手动记要点也完全走得通

## 4. 阶段二：内化（思考 + 复习）

> 知识单元（Block / Card / `^id` / `{{}}`）的格式与解析规则见 [`rnote-design.md`](rnote-design.md) §2，
> 那里已经定稿并有 24 项断言验证。本节只补工作流相关的东西：**怎么逼自己想、程度怎么量化、FSRS 怎么落地。**

### 4.1 加工工作台

打开 `00-输入/` 里的材料卡时，右侧多一个「加工」面板：

```
┌─────────────────────────┬──────────────────┐
│  材料卡（原料 + 摘录）    │  加工脚手架       │
│                         │                  │
│  ## 原文摘录             │  ① 一句话说清     │
│  - 间隔重复的核心是…      │  □ 已经写了       │
│  - 检索比重复阅读有效…    │  ② 我自己的例子   │
│                         │  □ 还没有         │
│  ## 我的加工             │  ③ 和已知的冲突   │
│                         │  □ 还没有         │
│  - 检索练习之所以有效…^rt │  ④ 能用在哪儿     │
│    - ? 为什么…？          │  □ 还没有         │
│                         │  ⑤ 边界在哪       │
│                         │  □ 还没有         │
└─────────────────────────┴──────────────────┘
```

### 4.2 思考脚手架：把"深度加工"拆成五问

你说的"思考、归纳、总结、抽象、举例、实践"，落地成**五个具体的动作**（面板上就是五条，勾了才算数）：

| # | 问题 | 对应你说的 |
| --- | --- | --- |
| ① | **一句话说清**：不用任何术语，这句话是什么？ | 归纳、总结 |
| ② | **我自己的例子**：我经历过的哪件事是这个道理？ | 举例、实践 |
| ③ | **和已知的冲突**：它和我原来相信的哪一点不一样？ | 思考、抽象 |
| ④ | **能用在哪儿**：明天我能拿它做什么决定？ | 实践 |
| ⑤ | **边界在哪**：什么情况下它不成立？ | 抽象、批判 |

这五条不是必填表单，而是**卡片生成的种子**：按 ③/④/⑤ 造出来的卡，才是"与自己相关"的卡，而不是"这个定义是什么"的复读卡。

### 4.3 提炼：把材料变成 Block

- 选中一段 → `Ctrl` + `Shift` + `B` → 变成 Block（补 `^id`），并**自动记下它来自材料卡的哪一段**（材料卡的反链里就能看到"被哪篇内化笔记引用了"）
- 已经想清楚的一句话 → `Ctrl` + `Shift` + `V` → 新建/追加到 `10-内化/<主题>.md`，同时把 status 推到 `internalizing`

### 4.4 AI 造卡：只出问题，不出答案

延续 `rnote-design.md` §6 阶段三的原则，这里强调一遍**为什么**：

> **AI 生成答案 = 把"内化"这一步外包出去了，正好毁掉这个阶段存在的意义。**
> 所以 AI 只做两件事：**从你的 Block 里提问**、**指出你可能没想到的角度**。
> 答案永远来自你的 Block 原文或你自己敲的字。

交互：`Ctrl` + `Shift` + `C` → 面板给出 **4-6 个候选问题**（带角度标签：辨析 / 应用 / 反例 / 边界），你勾选、改措辞、删掉不想要的，确认后才写进 Markdown。**没有一键全收。**

### 4.5 FSRS：直接上 FSRS，不做 SM-2 过渡

`rnote-design.md` 原计划"先 SM-2 再 FSRS"。**改主意了：直接做 FSRS**，理由：

- SM-2 只是热身，做完就得迁移排期数据，等于白写一遍
- FSRS 的实现不是难点——Rust 生态有官方 crate **`fsrs`（当前 6.6.2，含 Optimizer 与 Scheduler）**，参数、公式、优化器都是现成的
- 用户的收益是立刻的：同样的复习量，记住的东西更多（官方基准：同等留存率下复习量减少 20–30%）

排期状态**不放 JSON 文件，改用 SQLite**（`.rnote/rnote.db`）——评分是高频写、统计要聚合、
崩溃不能丢全部，这三条正好是 SQLite 的主场。完整设计见
[`rnote-storage.md`](rnote-storage.md)。现在的实现比那份文档更彻底：

- **库是全部**：笔记内容、树、块、卡片、复习状态全在库里；磁盘上**没有**第二份，
  应用不写 `.md` 也不读回来（只有"第一次打开一个已有文件夹"时把里面的 `.md` 收进来一次）
- **卡片自带快照**：建卡时把选中的块文字存进 `cards.source_text`，
  所以改正文、拆句、挪位置都不会动到已有卡片——不需要"块身份阶梯"那套认回机制

四档评分（`重来 / 困难 / 良好 / 简单`）直接映射 FSRS 的 `Again / Hard / Good / Easy`，快捷键 `1 2 3 4`。

### 4.6 "内化程度"怎么量化

你说"逐步达到较高理解程度"——**这事不能靠感觉，得有个数**。每篇内化笔记显示一个成熟度徽标：

```
成熟度 = 卡片覆盖率 × 复习成熟度

卡片覆盖率 = 挂了卡的 Block / 总 Block        （有没有提炼出来）
复习成熟度 = 熟练卡 / 总卡                     （有没有记住）
            熟练 := FSRS stability ≥ 21 天
```

| 成熟度 | 显示 | 含义 |
| --- | --- | --- |
| < 30% | `初加工` | 记了，但还没提炼 |
| 30–70% | `加工中` | 有卡片，还在反复 |
| > 70% | `熟练` | 可以拿它去输出了 |

工作台的三列看板上，每张卡片直接带这个徽标——**"哪些笔记值得现在动手输出"变成了一个可以排序的数字，而不是一种感觉。**

## 5. 阶段三：输出（结构化 + 归档）

### 5.1 输出笔记：来源可追溯

`20-输出/` 里是一篇正常的 Markdown，只是多了一行来源：

```markdown
---
status: output
type: output
sources: ["[[检索练习为什么有效]]", "[[卡片盒笔记法]]"]
audience: 公开
created: 2026-10-20
---

# 我是怎么用卡片盒记笔记的

（用自己的话讲一遍，不复制内化笔记的句子）
```

打开输出笔记时，右侧面板自动把 `sources` 和反链汇总成**来源区**：

```
来源
  检索练习为什么有效   12 个 Block · 成熟度 82%
  卡片盒笔记法         8 个 Block · 成熟度 64%
产出
  （还没有别的笔记引用这一篇）
```

**为什么把 `sources` 写成显式字段而不是只靠反链**：反链是"谁提到了我"（双向、可能噪音），`sources` 是"我这篇是基于什么写的"（单向、是真声明）。两个都要有。

### 5.2 费曼检查清单

输出面板上四条打勾项——**每条都对应一种"没真懂"的症状**：

- [ ] **不用术语能讲清**：出现术语的地方，后面有没有跟上大白话解释？
- [ ] **有自己的例子**：至少一个例子来自你自己的经历，而不是书里的
- [ ] **说了"所以呢"**：读者看完能改变哪个具体行为？
- [ ] **留了边界**：什么情况下这个结论不成立？

没勾完也能存（不阻塞写作），但**看板上会显示"待打磨"**。

### 5.3 归档与回流

- 输出完成 → 它引用的材料卡 status 自动变成 `archived`（材料消化完了），从待处理列表消失
- 输出笔记本身**也可以挂卡**：`- 这篇文章的核心论点是什么？`——**遗忘之后，复习会把你带回成品**，而不是从零重读
- FSRS 里 `lapses` 偏高的卡，复习界面给一个「跳回原文」按钮（内化笔记或输出笔记）

### 5.4 导出与分享

- 单篇导出：Markdown / 带样式的 HTML / PDF（用现有的 markdown-it 管线 + 打印样式）
- 「复制为公众号格式」：内联样式的 HTML，直接粘进编辑器
- 批量导出：把 `20-输出/` 打包成一个静态站点（第三阶段，不急）

## 6. 工作台：把三阶段装进一个界面

左侧工具栏加一项「**工作台**」（`Ctrl` + `Shift` + `W`），是每天打开应用的第一屏：

```
┌─ 今日 ────────────────────────────────────────────────┐
│  待处理 7      今日到期 23 张      待打磨 2 篇          │
│  [ 开始今日流程 ]                                      │
├───────────────┬───────────────┬───────────────────────┤
│  待处理 7      │  内化中 14     │  已输出 5              │
│ ─────────────  │ ─────────────  │ ─────────────          │
│ ▸ 心理学课 第3讲│ ▸ 检索练习…     │ ▸ 我是怎么用卡片盒…     │
│   课程 · 刚刚  │   熟练 82%     │   待打磨 · 3 天前      │
```

**「开始今日流程」**是一键串起来的引导（不是自动批处理，每一步你都能停下来）：

1. **清收集**：一条条过待处理的，每条只做三个决定之一（加工 / 归档 / 删）
2. **复习**：FSRS 队列，先到期旧卡、后新卡，配额到了就收工
3. **推输出**：把成熟度 > 70% 的列出来，问你"今天要不要把哪篇讲清楚？"

**看板支持拖动改状态**（包括往前和往后拖），拖动的本质就是改 frontmatter 里的 `status`——**所以看板是文件状态的视图，不是另一份数据**。

## 7. 数据格式汇总

```jsonc
// frontmatter：只加这一行也能用
---
status: inbox              // inbox | internalizing | output | archived（认中文）
type: course               // note | course | book | article | clip | idea | output
source: "得到 App · 心理学基础 · 第 3 讲"   // 可选
captured: 2026-10-06       // 可选，缺省用文件创建时间
sources: ["[[笔记名]]"]     // 只在输出笔记上用
audience: 公开             // 可选：公开 | 自己
---
```

```
<仓库文件夹>/
  .rnote/
    rnote.db         # SQLite：笔记内容 + 树 + 块 + 卡片 + FSRS 状态 + 复习历史
    backups/         # 每天首次打开时的快照，保留 14 份
    .gitignore       # 免得二进制库进你的 git 历史
  （材料、附件，以及第一次打开时被收进库的那些 .md）
```

**注意：笔记本体就在 `rnote.db` 里。** 删掉 `.rnote/` 等于清空这个仓库，所以
"换机器"是拷走整个文件夹，"回退"是取 `backups/` 里的一份快照，
"想要纯文本"是设置里的「导出全部为 Markdown」——它给出一份可读快照，但**不会被读回来**。

## 9. 路线图

**每个阶段都能独立使用**——做完 P0 就能开始用，不用等全部做完。

### P0 · 地基与捕获（把已有的笔记变成流水线）✅ **已完成**

1. ✅ `frontmatter` 的解析与写回（Rust 侧 `workflow.rs`，只改 `status` 一个键，不重排 YAML、不丢注释）
2. ✅ 状态字段 + **SQLite 索引**（`.rnote/rnote.db`，schema v1：`notes` 表），增量同步走 mtime 快路径
3. ✅ **工作台**：今日计数 + 三列看板 + 拖动改状态 + 积压老化（14 天标黄 / 30 天标红）
4. ✅ **快速捕获**（`Ctrl+Shift+I`）+ 收件箱按天成篇（`00-输入/收件箱/YYYY-MM-DD.md`）
5. ✅ 材料导入（`Ctrl+Shift+M` 或工作台按钮 → 附件进 `attachments/`，生成材料卡并按扩展名判类型）
6. ✅ 侧栏「工作台」入口 + 状态着色

**实现时的三处调整**（都写进了代码注释）：

- **看板多了一列「未分类」**。原设计是"没有 status 的老笔记不进看板"，但那样第一次打开工作台会是空的，
  看起来像坏了。改成第四列（视觉上退后一层），拖进前三列即可归类——交互一致，也不破坏"零打扰"。
- **块数 / 卡数暂用轻量正则统计**（数列表项、跳过任务项、统计 `{{}}`），只为算"分母"。
  P1 会换成与前端 `rnote.ts` 同源的解析器。
- **`rn_id` 的懒写入推迟到 P1**：笔记级现在用路径哈希兜底，真正需要稳定 id 的是卡片，而卡片在 P1。

**验收**：周一收的一堆材料，周五能在看板上清楚地看到"哪些还没动" ✅

### P1 · 内化闭环（这一步才真正改变行为）
7. 编辑器装饰：Block 圆点、`^id` 隐藏、卡片行着色（原 RNote 阶段一）
8. ✅ `Ctrl+Shift+C` 造卡 + 右侧卡片面板
9. ✅ **FSRS 排期**（`fsrs` crate + `.rnote/rnote.db` 的 `cards` 表）+ 四档评分复习视图
10. ✅ 左侧「复习」入口 + 今日到期徽标
11. 加工面板的**五问脚手架**

**建卡这条链落地时的两处调整**（都写进了代码注释）：

- **卡片只存在库里，不往正文写标记**。原设计是"卡片行 `- ? 问题` 写在 Block 下面"，
  但那样每次保存都要把正文改一遍，而且改一次正文就得重新认回卡片。
  现在的做法是：建卡时把选中的文字**快照**进 `cards.source_text`，
  正文从此与卡片无关——复习进度再也不会因为拆句、挪段而丢。
- **块由"选区"定义，不用先写 `^id`**。`Ctrl+Shift+B` 仍然可以给段落补一个 `^id`
  （给双链引用和"成块"的仪式感用），但**它不是建卡的前置条件**：
  选中一段直接 `Ctrl+Shift+C` 就能建卡，问题默认用草稿，想改问法再走弹窗。

**顺手修掉的三处老毛病**（都是"打开仓库之后界面不对"级别的）：

1. **补列不再看版本号**。升级流程原来是「`user_version` 到了就整段跳过」，
   于是一个 v5 之前建好的库（版本号 6、`notes` 表却没有 `front` 列）永远补不上，
   打开仓库时 `SELECT ... front ...` 直接报错，文件面板整片空掉
   （`.rnote/rnote.db` 的 `user_version = 6` 不等于表结构是新的）。现在每次打开都核对列，
   缺哪列补哪列，幂等、几十微秒。
2. **文件面板的树由路径推导**，不再只认 `parent_id`。v5 之后从磁盘导入的老笔记
   `parent_id` 一律为空，靠递归找子节点会得到一棵空树。
3. **老路径的 `.md` 重复行有人管了**。卡片时代之前路径带扩展名，迁移只搬了正文与卡片，
   老行留在表里：文件面板出现两份同名笔记，而且**真正的卡片挂在那份"空壳"上**。
   现在合并时**先把卡片挪到真身身上**（同一个问题只留一张），再删空壳；
   内容与磁盘镜像一模一样的空壳直接删掉，这样"库里删掉的笔记"不会下次打开又自己回来
   （删除时也会连带删掉镜像，并在 `meta` 里留下墓碑，`import_vault` 认这个墓碑）。

**验收**：走完"捕获 → 提炼 Block → 造卡 → 第二天复习 → 一周后重逢"。

### P2 · 输出与回流
12. 输出模板 + `sources` 字段 + 来源 / 产出面板
13. **成熟度徽标**与看板排序
14. 费曼检查清单
15. 归档流转（输出完成 → 材料自动归档）+ 输出笔记挂卡 + 「跳回原文」
16. 单篇导出（Markdown / HTML / PDF）

**验收**：一篇输出从"内化成熟度 80%"到发布，材料自动归档；一个月后凭复习能回到这篇成品。

### P3 · 智能与数据

18. AI 摘要 / 要点提取（材料卡 → 候选 Block）
19. 复习统计仪表盘（热力图、留存率、成熟度分布、各阶段吞吐）

## 附：为什么这套设计能活下来

同类工具失败的原因通常不是功能少，而是**流程太重、断了三天就再也接不上**。这套设计对抗它的地方：

- **捕获零决策**，所以永远不会"懒得记"
- **三层结构可选**，所以永远不会"今天不想复习就不敢打开应用"
- **复习配额有上限**，宁可少给，不让你被积压吓跑
- **全部装在一个文件夹里**，所以换机器就是拷文件夹；再加上每日快照与"导出全部为 Markdown"，
  数据不锁在云上，也不锁在这个应用里
